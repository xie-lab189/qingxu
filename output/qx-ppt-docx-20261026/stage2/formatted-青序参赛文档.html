一、作品背景与说明

1.1 作品背景

当代大学生与研究生普遍面临学业竞争、科研压力与就业焦虑。公开调研显示，高校学生焦虑与抑郁检出率显著高于社会平均水平；而市面上的"效率类"工具（待办、番茄钟、日程表）普遍是冷漠的催促者——只负责提醒"你还有 8 件事没做"，却从不关心使用者当下的情绪状态，反而加重复压。

我们观察到一组矛盾：人在情绪低落（疲惫、焦虑、压力大）时，决策力与执行力下降，但待办清单不会因此变短。硬撑的结果往往是全面崩盘，进一步打击自信。

1.2 作品定位

"青序"要做的是一个会照顾你心情的规划助手：把"情绪感知"作为第一输入，让任务管理随情绪自适应地"收"或"放"。它不是又一个效率工具，而是一个情绪友好的学术减压伙伴。

二、数据收集与处理

2.1 数据来源（主要渠道）

本作品的数据与知识来源可分为三类，兼顾权威性与时效性：

  1. 智谱 GLM 大模型 API（实时生成源）
    渠道：open.bigmodel.cn/api/paas/v4/chat/completions。权威性为国内头部大模型厂商、具备持续迭代能力；时效为实时调用、无陈旧风险。用途：三类智能体的自然语言对话生成。
  2. 本地原创治愈语料库（自研数据）
    规模：9 类情绪 × 300 条 = 2700 条原创短句。全部原创、无外部版权风险、离线可用、永不失效。用途：树洞 VentBox 与主动安抚的离线语料。
  3. 用户行为数据（应用内产生）
    内容：情绪打卡、任务完成状态、日记文本。存储以本地（localStorage）为主、后端 JSON 文件为辅，最小化上云。用途：驱动情绪—任务联动、跨设备同步。

2.2 知识库内容

  • 三类智能体人格知识库：规划师 / 陪伴者 / 督促官各自的 System Prompt 与话术库。
  • 情绪—任务联动规则库：保护模式的触发条件与任务重排逻辑（硬规则，不依赖大模型）。
  • 2700 条治愈短句情绪映射库：短句按 9 类情绪索引，供随机/情境推荐。

2.3 预处理与利用

关键预处理流程（数据流）：

用户输入（情绪打卡 / 一句话需求）
↓
[情绪识别] 归类为 9 类情绪之一
↓
[联动规则引擎] 负面情绪 → 触发"保护模式"；正面 → 常规规划
↓
[任务重排 / 语料推荐] 保留必须项、顺延非必须项 / 推送治愈短句
↓
[本地持久化] localStorage + 后端 JSON（跨设备同步）
↓
[夜间提醒] 20:00 由定时器触发邮件，推送当日总结与第二日建议

使用的工具与 API：WorkBuddy 智能体编排（Agent 调度）；智谱 API（对话生成）；Express 后端 + nodemailer + QQ 邮箱 SMTP（邮件发送）；EasyCron 外部定时器（每日北京时间 20:00 调用 /api/cron/reminders）。

在 AI Agent 设计中的用途：情绪标签驱动任务调度策略的选择；本地语料在大模型不可用或需隐私保护时作为降级与补充；用户行为数据形成"情绪—任务"闭环，使 Agent 的建议具备个性化与上下文连续性。

三、分析过程

3.1 分析方法选择

作品处于产品早期、缺乏海量样本，因此采用可解释、轻量、规则优先的分析组合：

  • 场景化设计分析（用户旅程映射）：梳理"情绪低谷 → 打开应用 → 得到计划"的体验断点。
  • 规则驱动的逻辑验证：对保护模式做"前后任务集"对比，验证减负效果。
  • 轻量统计：基于用户日志统计情绪分布与任务顺延率。

选择依据：避免黑箱模型，保证每一处干预都可解释、可审计、可答辩。

3.2 问题理解与逻辑论证

关键发现：

  • 负面情绪下"硬撑"会使完成率显著下降；
  • "重要不紧急"事项（如长期复习、健身）最易被拖延积压；
  • 用户需要的不是"更多任务"，而是"更少但更对的任务"。

数据实例（保护模式减负论证）：某用户"疲惫日"原待办 8 项：重要且紧急 2 项、紧急不重要 1 项、重要不紧急 3 项、不重要不紧急 2 项。启用保护模式后：保留【重要且紧急 2 + 紧急不重要 1】共 3 项，顺延其余 5 项。预估完成率从约 25%（8 项中勉强做 2 项）提升至 100% 保底（3 项全部可完成），心理压力下降、成就感上升。

分析流程（思维导图式）：情绪输入 → 规则判定（正/负） → 正向：常规四象限规划 / 负向：保护模式重排 → 输出计划 + 安抚语料 → 用户反馈回流。

四、创新性与独特视角

4.1 创新点（重点）

创新点一：情绪自适应的任务调度（保护模式）。行业现有 GTD / 四象限工具一律"平等对待所有任务"。青序首创将心理保护机制嵌入任务调度：当检测到负面情绪时，自动保留"核心利益（重要且紧急）"与"时间底线（紧急不重要）"两类必须项，将其余事项科学顺延、平摊到后续天数。把"照顾心情"变成可执行的工程规则，而非一句口号。

创新点二：本地离线治愈语料 + 大模型混合架构。树洞 VentBox 与主动安抚不依赖大模型、不联网、不上传隐私，由 2700 条本地原创短句支撑；只有在需要深度对话时才调用智谱 GLM。该架构带来三重优势：隐私安全（敏感情绪/日记本地化）、稳定可靠（网络波动不影响基础安抚）、成本可控（减少对大模型调用的依赖）。

4.2 独特视角（跨学科融合）

本作品是心理学 × 管理学 × 人工智能 × 教育学的交叉实践：

  • 心理学：情绪调节理论指导"先安抚、再规划"的交互顺序；
  • 管理学：艾森豪威尔四象限提供任务优先级骨架；
  • 人工智能：大模型 Agent 实现自然语言理解与个性化对话；
  • 教育学：聚焦"学术场景减压"这一真实痛点，落地于大学生日常。

五、结果解释与建议

5.1 结果解读

Agent 在真实场景中的价值体现在三层：

  1. 被看见：情绪打卡让用户的负面状态被系统识别并回应，降低孤独感；
  2. 被减负：保护模式用工程规则把"不可能完成的清单"变成"今天一定能完成的三件事"；
  3. 被陪伴：树洞与督促官提供持续、稳定的外部支持，形成行为惯性。

5.2 存在问题与优化建议

  1. 问题：大模型依赖网络且偶有幻觉。建议：关键调度逻辑已本地化（规则引擎兜底），后续可将更多"安全话术"离线化，并对大模型输出做敏感词与事实约束。
  2. 问题：语料覆盖度有限。建议：引入用户点赞/收藏反馈，对 2700 条语料做热度排序与增量补充。
  3. 问题：个性化深度不足。建议：基于长期情绪趋势构建用户画像，实现"周期性低谷预警"与差异化建议。

5.3 风险识别与应对

  • 数据安全风险（情绪、日记属敏感信息）：以本地存储为主、最小化上云；后端采用独立密钥管理（智谱 Key、QQ 授权码、Cron Token 隔离存储）。
  • 大模型幻觉/不当建议风险：保护模式硬规则兜底，语料约束输出边界，避免其给出有害或越界建议。
  • 邮件服务依赖风险：定时触发链路（EasyCron → 后端 → QQ SMTP）任一环节失败会导致漏发；建议增加失败重试与多通道兜底（如站内信）。

六、应用结果呈现

6.1 应用对话界面

  • 三大智能体对话页：规划师（生成计划）、陪伴者（日常聊天）、督促官（设提醒），人格与话术各异。
  • 情绪打卡卡片：9 类情绪一键点选，触发联动。
  • 保护模式横幅：负面情绪下展示"今天只保留必须完成的【重要且紧急】和【紧急不重要】任务，其余已顺延平摊到后续天数。完成保底，就是胜利。"
  • 树洞 VentBox：离线倾诉，随机推送治愈短句。

6.2 提示词示例与链接

以下提示词均已在线上智能体中实测可用：

  1. 规划类："我今天很焦虑，论文还没动，帮我安排今晚怎么过。"
    → 规划师输出带保护模式的精简计划，并附带安抚语。
  2. 陪伴类："陪我聊聊吧，最近有点孤独。"
    → 陪伴者/树洞回应治愈短句，不评判、只接纳。
  3. 督促类："晚上 8 点提醒我背 50 个单词。"
    → 督促官设置提醒，并由系统在北京时间 20:00 推送邮件。
